# 客户端表现层契约 v0.1

## 目标

客户端只负责显示、交互和播放动画，不判定棋子能否移动、撞机、跳跃、获胜等规则结果。Cocos Creator 接入后将消费 `@orange-ludo/client-model` 提供的三类数据。

## 三层接口

1. `PortraitBoardLayout`：归一化的棋盘节点、基地机位、棋盘区域和 HUD 锚点。UI 设计定稿后只替换布局数据，不需改规则。
2. `ClientViewState`：将权威游戏状态转为可渲染数据，包括棋子位置、可选状态、叠机序号、15 秒倒计时和当前玩家。
3. `AnimationCue[]`：将规则事件按原顺序转为骰子、逐格移动、跳跃、飞行、撞回、阻挡、换手和胜利动画指令。

## 坐标规则

- 全部坐标使用 `0..1` 归一化值，适配不同屏幕尺寸。
- `boardViewport` 是竖屏中棋盘的安全区域；节点坐标相对于棋盘区域。
- 当前布局是开发占位版，保证 52 个公共格、起飞坪、专属终点道和基地机位都可寻址。
- 美术定稿后，通过同一契约导入精确坐标，不修改规则引擎。

## 交互边界

- 游戏内核返回合法棋子 ID，客户端只高亮这些棋子。
- 玩家点击后只提交棋子 ID；最终移动路径仍由内核生成。
- 动画播放期间锁定棋盘交互，播放完毕后再显示新状态。
- 倒计时展示使用客户端时间，超时结果最终由对局控制器或服务端确认。
